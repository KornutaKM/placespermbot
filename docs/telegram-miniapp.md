# Telegram Mini App: первый работающий интерфейс

## Что входит в MVP-116

Мини-приложение — отдельный мобильный веб-интерфейс **внутри Telegram**,
открываемый командой `/app` или кнопкой главного меню, когда настроен HTTPS URL.
Обычный Telegram-бот, его polling и все его команды продолжают работать.

Первая версия использует существующие городские каталоги:
- выбор города и сохранение этого выбора в **существующей SQLite-базе**;
- визуальная главная страница, поиск мест, категории, фильтры;
- карточки достопримечательностей с длительностью осмотра и ссылкой Google Maps;
- готовые редакционные маршруты и ссылки на сегменты пути;
- адаптация для узких мобильных экранов, Telegram WebApp SDK.
- избранные достопримечательности: сердечки в карточках, отдельная вкладка «Избранное», сохранение и удаление через общий SQLite-репозиторий бота при подтверждённой Telegram-сессии (MVP-117).
- интерактивная карта города с координатами достопримечательностей, поиском, фильтрами и переходом к карточке места (MVP-118). Карта доступна в режиме просмотра; новый интерфейс не записывает местоположение пользователя.
- «Мой гид»: общая статистика, прогресс изучения города, избранное, отметки посещения, сохранённые маршруты и независимая история пройденных маршрутов. Просмотр и изменение личных данных требуют проверенного Telegram initData и выбранного города (MVP-119).
- «Свой маршрут» (MVP-120): время 2/4/6 часов, одна из семи тем, исключение посещённых мест (только Telegram-пользователь), раздельное время осмотра/ходьбы/резерва, остановки на карте по требованию и Google Maps-ссылки, сохранение в «Мой гид».
- Редактор остановок (MVP-121): убрать остановку или переместить её выше/ниже непосредственно в результате конструктора. После каждой правки сервер пересчитывает время, расстояния и карты; новая версия сохраняется отдельным маршрутом только по нажатию «Сохранить»; обычный бот и ранее сохранённые маршруты не меняются.

Это **не** полный паритет с Telegram-чатом. Добавление произвольных новых остановок, персональные рекомендации на основе интересов, профессиональная маршрутизация по дорожной сети и фотографии — отдельные будущие этапы.
В интерфейсе не публикуются выдуманные рейтинги и графики транспорта.

## Архитектура и безопасность

- `bot` — неизменный aiogram polling-сервис.
- `web` — FastAPI + uvicorn, статические HTML/CSS/JS и каталог API.
- `GET /api/cities` и `GET /api/catalogs/{city_slug}` — публичные,
  поскольку каталоги публичны и не содержат пользовательских данных.
- `GET /api/me/favorites/{city_slug}`, `PUT/DELETE /api/me/favorites/{city_slug}/{place_slug}` — требуют подписанный `initData`, выбранный текущий город и действительный slug места; повторные запросы идемпотентны. Чужие пользователи и другие города не могут быть изменены этим запросом.
- `GET /api/me/guide/{city_slug}` — агрегированный read-only профиль: статистика, сохранённые/пройденные маршруты (сначала существующие snapshot из SQLite), избранные и посещённые slugs. Устаревшие объекты каталога скрываются из списков, но не удаляются из БД.
- `PUT/DELETE /api/me/visited/{city_slug}/{place_slug}` — идемпотентные отметки посещений. `PUT /api/me/saved-routes/{city_slug}/{route_id}/complete` использует существующую транзакционную логику завершения маршрутов; `DELETE /api/me/saved-routes/{city_slug}/{route_id}` удаляет только сохранённый маршрут. Удаление в интерфейсе требует отдельного подтверждения; пройденные маршруты остаются в истории.
- Все личные эндпоинты проверяют HMAC/срок Telegram initData и принадлежность к активному городу, не принимают пользовательский ID с клиента.
- `POST /api/routes/{city_slug}/preview` доступен в браузерном просмотре без персональных фильтров; запрос с `exclude_visited=true` требует подписанный `initData` и выбранный город. Алгоритм не принимает произвольные точки и применяет ограничение 5 км по прямой между соседними остановками.
- `POST /api/me/routes/{city_slug}/save` требует подписанную Telegram-сессию, выбранный город, допустимые время/тему и `expected_route_id`. Сервер заново рассчитывает маршрут и сверяет отпечаток со снимком предпросмотра: клиент не может подсунуть slugs остановок или незаметно сохранить изменённый маршрут. При расхождении возвращается 409, запись в SQLite не выполняется. Повторное сохранение идентично по route ID.
- Мини-карта остановок загружается только по нажатию «Показать остановки на карте» и показывает схему расположения, **не** дорожную сеть и не GPS-навигацию. Нет сохранения геопозиции пользователя.
- `POST /api/routes/{city_slug}/edit` принимает исходный `base_route_id` и выбранный порядок/подмножество его точек. Сервер пересобирает исходный маршрут заново и проверяет, что каждая остановка действительно была выбрана планировщиком: подмена, повторы, полностью пустой маршрут, переходы более 5 км по прямой и превышение бюджета запрещены. Без персонального фильтра предпросмотр редактирования доступен локальному браузеру; с `exclude_visited=true` требуется подписанный пользователь и активный город.
- `POST /api/me/routes/{city_slug}/save-edited` требует подписанную сессию, проверяет актуальный исходный маршрут и **повторно** пересчитывает отредактированный вариант перед записью по его `expected_route_id`. Изменение сохранённого ранее маршрута не производится; создаётся отдельная версия с собственным ID. Ошибки 409 требуют пересоздать маршрут, 422 — проверить допустимость изменений.
- `GET /api/me` и `POST /api/me/city` — только с валидным заголовком
  `X-Telegram-Init-Data` из `Telegram.WebApp.initData`. Сервер проверяет
  HMAC SHA-256 через секрет `WebAppData`, возраст auth_date, отсутствие
  повторяющихся параметров и тип ID пользователя.
- Данные `initDataUnsafe` никогда не используются для аутентификации;
  фронтенд не получает бот-токен. Не открывайте CORS для всех сайтов.
- Telegram-клиент должен иметь возможность встроить веб-страницу в iframe;
  не добавляйте `X-Frame-Options: DENY/SAMEORIGIN` в reverse proxy.
- Прокси должен передавать HTTPS-запросы к локальному веб-сервису и ограничивать
  размер запросов; используйте TLS, логирование без initData и контроль доступа
  к резервным копиям. **Не публикуйте порт 8080 напрямую в Интернет.**

## Карта, внешние ресурсы и приватность

- Библиотека Leaflet 1.9.4 загружается из `unpkg.com` с закреплённой версией
  и SHA-256 Subresource Integrity. Карта открывается отдельной вкладкой;
  только при её открытии загружаются тайлы OSM из
  `https://tile.openstreetmap.org/{z}/{x}/{y}.png`.
- Запросы за тайлами выполняет браузер, поэтому OpenStreetMap получает IP,
  User-Agent, origin сайта и координаты просматриваемой области (в номерах
  тайлов). Идентификатор Telegram, токен бота и `initData` тайлам не передаются.
- Атрибуция OpenStreetMap отображается внутри карты. Для доступа к тайлам
  применяется `referrerPolicy: strict-origin-when-cross-origin` (вместо
  полного запрета Referer). Оставьте обычное кэширование тайлов браузером;
  никаких фоновых загрузок, скачивания городов или предзагрузки тайлов нет.
- `tile.openstreetmap.org` — бесплатный общественный ресурс без SLA, не
  предназначенный для высоконагруженного коммерческого сервиса. Перед
  публичным ростом аудитории потребуется выбрать устойчивого провайдера тайлов,
  проверить его тарифы, условия и политику конфиденциальности.
- Если CDN или тайлы недоступны, пользователь всё равно видит фильтруемый
  список достопримечательностей. Маркеры не строят дорожные маршруты:
  для навигации остаются ссылки Google Maps из карточек.

Правила OSM: https://operations.osmfoundation.org/policies/tiles/
Leaflet: https://leafletjs.com/

## Локальный просмотр

После клонирования нужного коммита можно открыть интерфейс в браузере:

```powershell
docker compose build --build-arg "PLACES_BUILD_SHA=$(git rev-parse HEAD)" bot web
docker compose up -d --no-build bot web
docker compose ps
```

Адрес на той же машине: `http://127.0.0.1:8080/`. Здесь работает
**режим просмотра**: каталоги доступны, но выбор города и избранное нельзя
сохранить или изменить без подписанного initData. Кнопки сердечек в таком режиме
неактивны; не имитируют сохранение на устройстве.

Если ваша локальная установка находится на старом SHA, не нужно обновлять её
после каждого PR: поддерживается [пакетное обновление Windows](local-windows-update.md).
Скрипт создаёт резервную копию SQLite и обновляет **оба** сервиса.

## Публикация в Telegram: пока только после настройки HTTPS

1. Разместите веб-сервис на доступном по HTTPS домене
   (например, `https://guide.example.com/`) за TLS reverse proxy. Прокси может
   работать на отдельном сервере и обращаться к приложению по защищённому
   каналу. Локальный `127.0.0.1:8080` не виден Telegram.
2. Установите в закрытом `.env`:
   `PLACES_MINI_APP_URL=https://guide.example.com/`.
   Токен `PLACES_BOT_TOKEN` остаётся только на сервере, в Telegram и
   репозиторий не передаётся.
3. Вручную, в удобное время, выполните одно проверенное пакетное обновление
   и убедитесь, что `https://guide.example.com/healthz` отвечает успешно.
4. Откройте бота в Telegram и используйте `/app`. Дополнительно можно
   настроить Main Mini App / Menu Button в @BotFather; это не происходит
   автоматически при merge PR.
5. Проверьте: новый пользователь выбирает город; после повторного запуска
   Mini App выбор сохранился; в обычном боте `/city` показывает тот же город;
   другой аккаунт Telegram не может изменить ваш город.

До выполнения этих шагов **Mini App в Telegram не опубликован**. Успешный
GitHub CI подтверждает исходники, тесты и Docker-упаковку, но не публичный HTTPS
и не реальную работу на устройстве пользователя.

Справочник Telegram: https://core.telegram.org/bots/webapps
