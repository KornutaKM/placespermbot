# Telegram Mini App: первый работающий интерфейс

## Что входит в MVP-116

Мини-приложение — отдельный мобильный веб-интерфейс **внутри Telegram**,
открываемый командой `/app` или кнопкой главного меню, когда настроен HTTPS URL.
Обычный Telegram-бот, его polling и все его команды продолжают работать.

Первая версия использует существующие городские каталоги:
- выбор города и сохранение этого выбора в **существующей SQLite-базе**;
- визуальная главная страница, поиск мест, категории, фильтры;
- карточки достопримечательностей с длительностью осмотра и ссылкой Google Maps;
- готовые редакционные маршруты и ссылки на сегменты пути;
- адаптация для узких мобильных экранов, Telegram WebApp SDK.

Это **не** полный паритет с Telegram-чатом. Избранное, посещения, персональные
маршруты, интерактивная карта и фотографии — отдельные будущие этапы.
В интерфейсе не публикуются выдуманные рейтинги и графики транспорта.

## Архитектура и безопасность

- `bot` — неизменный aiogram polling-сервис.
- `web` — FastAPI + uvicorn, статические HTML/CSS/JS и каталог API.
- `GET /api/cities` и `GET /api/catalogs/{city_slug}` — публичные,
  поскольку каталоги публичны и не содержат пользовательских данных.
- `GET /api/me` и `POST /api/me/city` — только с валидным заголовком
  `X-Telegram-Init-Data` из `Telegram.WebApp.initData`. Сервер проверяет
  HMAC SHA-256 через секрет `WebAppData`, возраст auth_date, отсутствие
  повторяющихся параметров и тип ID пользователя.
- Данные `initDataUnsafe` никогда не используются для аутентификации;
  фронтенд не получает бот-токен. Не открывайте CORS для всех сайтов.
- Telegram-клиент должен иметь возможность встроить веб-страницу в iframe;
  не добавляйте `X-Frame-Options: DENY/SAMEORIGIN` в reverse proxy.
- Прокси должен передавать HTTPS-запросы к локальному веб-сервису и ограничивать
  размер запросов; используйте TLS, логирование без initData и контроль доступа
  к резервным копиям. **Не публикуйте порт 8080 напрямую в Интернет.**

## Локальный просмотр

После клонирования нужного коммита можно открыть интерфейс в браузере:

```powershell
docker compose build --build-arg "PLACES_BUILD_SHA=$(git rev-parse HEAD)" bot web
docker compose up -d --no-build bot web
docker compose ps
```

Адрес на той же машине: `http://127.0.0.1:8080/`. Здесь работает
**режим просмотра**: каталоги доступны, но выбор города не сохраняется
как предпочтение Telegram-пользователя без подписанного initData.

Если ваша локальная установка находится на старом SHA, не нужно обновлять её
после каждого PR: поддерживается [пакетное обновление Windows](local-windows-update.md).
Скрипт создаёт резервную копию SQLite и обновляет **оба** сервиса.

## Публикация в Telegram: пока только после настройки HTTPS

1. Разместите веб-сервис на доступном по HTTPS домене
   (например, `https://guide.example.com/`) за TLS reverse proxy. Прокси может
   работать на отдельном сервере и обращаться к приложению по защищённому
   каналу. Локальный `127.0.0.1:8080` не виден Telegram.
2. Установите в закрытом `.env`:
   `PLACES_MINI_APP_URL=https://guide.example.com/`.
   Токен `PLACES_BOT_TOKEN` остаётся только на сервере, в Telegram и
   репозиторий не передаётся.
3. Вручную, в удобное время, выполните одно проверенное пакетное обновление
   и убедитесь, что `https://guide.example.com/healthz` отвечает успешно.
4. Откройте бота в Telegram и используйте `/app`. Дополнительно можно
   настроить Main Mini App / Menu Button в @BotFather; это не происходит
   автоматически при merge PR.
5. Проверьте: новый пользователь выбирает город; после повторного запуска
   Mini App выбор сохранился; в обычном боте `/city` показывает тот же город;
   другой аккаунт Telegram не может изменить ваш город.

До выполнения этих шагов **Mini App в Telegram не опубликован**. Успешный
GitHub CI подтверждает исходники, тесты и Docker-упаковку, но не публичный HTTPS
и не реальную работу на устройстве пользователя.

Справочник Telegram: https://core.telegram.org/bots/webapps
