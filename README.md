# Places Russia Bot

Telegram-гид по городам России. Активные seed-каталоги: **Санкт-Петербург** и **Пермь**.

## Что уже реализовано

- /start, /city, /profile, /export и главное меню города;
- профиль «Мой гид» с city-scoped прогрессом, настройками и JSON-экспортом данных;
- пользовательский активный город с сохранением в SQLite;
- расширяемый multi-city catalog layer;
- каталог Санкт-Петербурга из 22+ проверяемых точек;
- второй реальный каталог — Пермь из 8 стабильных seed-точек;
- постраничный вывод категорий, избранного и персональных рекомендаций;
- контекстная stateless-навигация назад из карточки места;
- provenance каждой точки: источник и дата проверки;
- категории: достопримечательности, необычные места, музеи, парки, с детьми, бесплатно;
- карточки мест с геопозицией и пешеходным deep-link «Маршрут сюда»;
- «Что рядом» по координатам выбранной точки;
- «Рядом со мной» по одноразовой Telegram-геопозиции;
- детерминированный поиск по названию, описанию, району и тегам;
- готовые редакционные маршруты;
- конструктор маршрутов на 2 / 4 / 6 часов по интересам;
- опциональный старт маршрута от геопозиции пользователя;
- расчёт маршрута из visit time + ориентировочных пеших переходов;
- открытие готовых и сгенерированных прогулок в Google Maps;
- длинные маршруты автоматически разбиваются на mobile-safe сегменты;
- постоянное пользовательское избранное в SQLite;
- отдельная история посещённых мест с mark/unmark;
- сохранённые пользовательские маршруты из конструктора;
- версионированные SQLite migrations без удаления named volume;
- явные пользовательские интересы и детерминированная подборка «Для меня»;
- реальные внешние каталоги экскурсий Sputnik8 и Tripster с provenance/freshness для поддерживаемого города;
- live-афиша Петербурга через Яндекс Афишу и KudaGo; неподдерживаемые города fail-closed без fake data;
- Docker с persistent volume и healthcheck;
- CI с Ruff, pytest и Docker image smoke.

## Города

При первом `/start` бот не назначает город молча: пользователь явно выбирает один из
доступных каталогов. Технический `PLACES_CITY_SLUG` остаётся fallback для middleware и
runtime-совместимости, но не записывается как пользовательское предпочтение без нажатия
`city:set:...`. Устаревшее предпочтение на удалённый каталог также возвращает пользователя
к явному выбору города.

CityCatalog не содержит city-specific логики в Telegram handlers. Выбор города сохраняется
по пользователю, а favorites, interests, visited, dismissed и saved routes изолированы по
`user_id + city_slug`.

Сейчас доступны:

- **Санкт-Петербург** — основной расширенный каталог;
- **Пермь** — второй production seed, подтверждающий multi-city flow на реальных данных.

Для Перми локально хранятся только стабильные карточки и редакционные маршруты. Динамические
афиши, экскурсии, цены и расписания не копируются из Петербурга и не выдумываются: если
provider для города не зарегистрирован, соответствующий раздел отвечает fail-closed.


## Конструктор маршрутов

Конструктор не использует LLM для выбора фактов и не придумывает точки. Он работает только с
активным CityCatalog.

Пользователь выбирает:

1. бюджет времени: 2 / 4 / 6 часов;
2. интерес: классика, музеи, архитектура, прогулки, необычные места, с детьми или бесплатно.

Алгоритм учитывает ориентировочное время посещения и пешие переходы со скоростью 4,5 км/ч.
Точка добавляется только если целиком помещается в оставшийся бюджет времени.

Пользователь может явно нажать «📍 Начать рядом со мной» и передать Telegram-геопозицию. Тогда
переход от текущего места до первой точки тоже входит в бюджет. Эти координаты хранятся только
в текущем FSM-сеансе и очищаются после построения маршрута или выхода из сценария.

## Локальный запуск

Создайте .env из .env.example, укажите Telegram Bot Token, затем выполните:

    python -m venv .venv
    pip install -e ".[dev]"
    python -m app.main

Или:

    docker compose up --build

## Переменные окружения

    PLACES_BOT_TOKEN=123456:replace-me
    PLACES_ENVIRONMENT=development
    PLACES_CITY_SLUG=saint-petersburg
    PLACES_DATABASE_PATH=data/places.db
    PLACES_SPUTNIK8_AFFILIATE_URL=
    PLACES_TRIPSTER_AFFILIATE_URL=
    PLACES_YANDEX_AFISHA_URL=
    PLACES_KUDAGO_EVENTS_URL=

## Данные

Стабильный seed-каталог хранится отдельно от Telegram-handlers. Контент, который может меняться
(цены, часы работы, доступность, экскурсии, события), не должен становиться «вечной правдой»
в коде без источника и даты проверки.

SQLite используется только как persistence для первого MVP. Архитектура должна позволить
перенести пользовательские данные и каталог в PostgreSQL/PostGIS по мере роста проекта.


## Внешняя карта

Для открытия прогулки используется официальный Google Maps URL format без API key. Ссылка
строится только из координат точек каталога. В одной directions-ссылке используется максимум
5 точек: origin + до 3 waypoints + destination. Более длинная прогулка разбивается на
последовательные сегменты с общей граничной точкой.


## Рядом со мной

Пользователь может явно запросить ближайшие места и передать Telegram-геопозицию. Бот
показывает до 8 точек каталога в радиусе 10 км, отсортированных по расстоянию. Координаты
используются только для текущего запроса и не записываются в SQLite.


## Экскурсии и внешние провайдеры

Раздел «Экскурсии» использует provider layer. Базовая production-конфигурация ведёт в
официальные live-каталоги Санкт-Петербурга у Sputnik8 и Tripster. Локально не сохраняются
цены, расписание или availability, потому что эти поля быстро меняются.

Каждая provider record содержит:

- provider id и имя;
- официальный source URL;
- пользовательский catalog URL;
- дату последней проверки источника;
- integration mode.

После регистрации в партнёрских программах можно задать affiliate URL через env. Override
принимается только по HTTPS и только для allowlisted доменов соответствующего провайдера;
невалидный URL автоматически откатывается на официальный каталог.

Sputnik8 публично указывает API-интеграцию как партнёрский инструмент «по запросу». Когда
будут выданы реальные API credentials и документация контракта, можно добавить API adapter
за существующим provider interface без изменения Telegram flow.


## События и афиша

Раздел «События» ведёт в live-каталоги Яндекс Афиши и KudaGo для Санкт-Петербурга.
Динамические даты, цены и наличие билетов не сохраняются в локальной базе. Для каждого
источника сохраняются provider id, source URL, пользовательский catalog URL, integration mode
и дата последней проверки.

URL override допускается только по HTTPS и только на allowlisted домене конкретного источника.
Некорректное значение автоматически заменяется официальным catalog URL.


## Персонализация

Раздел «Для меня» использует только интересы, которые пользователь выбрал явно. Поддерживаются
классика, музеи, архитектура, прогулки, необычные места, варианты с детьми и бесплатные места.

Интересы хранятся в SQLite с ключом `user_id + city_slug + interest`. Бот не выводит скрытые
предпочтения из геопозиции, истории просмотров или других сигналов. Рекомендации строятся
детерминированным скорингом по категориям и тегам текущего CityCatalog. Точки, которые пользователь
явно отметил как посещённые, исключаются из «Для меня» до применения лимита выдачи.


## Provenance каталога

Каждая `Place` содержит обязательный `PlaceSource`:

- название источника;
- HTTPS URL;
- дату последней проверки.

Карточка места показывает источник пользователю. Seed-каталог не хранит динамические часы
работы, цены или наличие билетов как статические значения: такие сведения должны приходить
из live-provider слоя либо проверяться пользователем у официального источника.

Текущая база расширена объектами: Юсуповский дворец, Музей Фаберже, Эрарта,
Гранд Макет Россия, Елагиноостровский дворец, Ботанический сад Петра Великого,
Мариинский театр и Дом компании «Зингер».


## Пагинация списков

Длинные пользовательские списки не зависят от in-memory page state. Номер страницы кодируется
в callback, а содержимое восстанавливается из текущего каталога или SQLite. Размер страницы —
6 мест. Это означает, что кнопки навигации остаются корректными после рестарта контейнера.

Пагинация включена для:

- категорий каталога;
- избранного;
- раздела «Для меня».

Короткие bounded-выдачи поиска и «Рядом со мной» остаются без отдельной пагинации.


## Маршрут к месту

В карточке каждой точки есть кнопка «🚶 Маршрут сюда». Она открывает Google Maps directions
с `destination` из проверенных координат каталога, `travelmode=walking` и
`dir_action=navigate`. Параметр `origin` намеренно не передаётся: стартовая точка
определяется на стороне карты/устройства, поэтому боту не нужно получать или сохранять
геопозицию пользователя для этого сценария.


## Проверка Docker runtime

После запуска:

    docker compose up --build -d
    docker compose ps

после короткого start period контейнер должен перейти в состояние `healthy`.

Docker healthcheck не обращается к Telegram API. Он проверяет:

- что bot token настроен;
- что активный city catalog существует и не пуст;
- что SQLite уже инициализирована;
- что присутствуют таблицы `favorites`, `user_interests`, `user_city_preferences` и `visited_places`.

Для диагностики:

    docker inspect --format='{{json .State.Health}}' placespermbot-bot-1

CI дополнительно собирает реальный Docker image и запускает внутри него network-free
`python -m app.smoke`, чтобы ловить ошибки упаковки, отсутствующие модули, broken imports и загрузку реального `app.main`.


## SQLite migrations

Схема локальной БД версионируется таблицей `schema_migrations`. Миграции выполняются
до запуска Telegram polling и применяются строго по порядку.

Текущие версии:

1. `create_favorites`;
2. `create_user_interests`;
3. `create_user_city_preferences`;
4. `create_visited_places`;
5. `create_saved_routes`;
6. `create_dismissed_places`.

Переход со старой БД безопасен: migrations используют существующие таблицы и не удаляют
сохранённые строки. Повторный запуск idempotent. Если volume содержит неизвестную более новую
версию схемы, приложение останавливается fail-closed вместо попытки работать с несовместимыми
данными.

При обычном обновлении контейнера named volume `places-data` сохраняется. Не используйте
`docker compose down -v`, если хотите сохранить пользовательские данные.


## Контекстная навигация

Карточка места сохраняет короткий navigation context прямо в Telegram callback:

- `c.<category>.<page>` — вернуться в ту же страницу категории;
- `f.<page>` — вернуться в ту же страницу избранного;
- `p.<page>` — вернуться в ту же страницу «Для меня»;
- `r` — вернуться к маршрутам;
- `s` — начать новый поиск;
- `h` — вернуться в главное меню;
- `n.<origin>@<parent>` — вернуться к исходному месту из «Что рядом».

Server-side navigation stack не используется. Поэтому кнопки остаются валидными после
рестарта процесса/контейнера. Старые callback без navigation context поддерживаются и
безопасно возвращают пользователя к категориям. Все формируемые callback ограничены
лимитом Telegram в 64 байта.


## Multi-city и выбор города

`PLACES_CITY_SLUG` теперь задаёт только default/fallback город. Активный город пользователя
хранится отдельно в SQLite по Telegram `user_id` и выбирается через кнопку
«🌆 Сменить город» или команду `/city`.

Каждый Telegram update проходит через `CatalogMiddleware`, который резолвит пользовательский
`CityCatalog` и помещает его в request-scoped context. Поэтому каталог одного пользователя
не может протечь в запрос другого, а handlers не зависят от конкретного города.

Если сохранённый city slug больше не зарегистрирован в текущей версии приложения, resolver
безопасно использует default catalog. Сохранить неизвестный город через UI/service нельзя.

Live-провайдеры экскурсий и событий также city-scoped: для города без подключённого provider
раздел fail-closed показывает, что интеграция пока недоступна, вместо ссылок на другой город.


## Посещённые места

Избранное и история посещений — независимые состояния:

- «❤️ В избранное» означает, что место сохранено пользователем;
- «✅ Уже был» означает, что пользователь явно отметил место как посещённое.

История хранится в `visited_places` с ключом
`user_id + city_slug + place_slug`. Раздел «✅ Посещённые» показывает историю только для
текущего пользователя и активного города, с той же stateless-пагинацией, что и избранное.

Отметку можно снять из карточки места. Это не меняет favorite state. Аналогично изменение
избранного не меняет историю посещений.

Посещённые места исключаются из персональной подборки «Для меня». Если все подходящие под
выбранные интересы точки уже посещены, бот показывает это явно вместо повторной рекомендации.


## Профиль «Мой гид»

Экран «👤 Мой гид» доступен из главного меню и командой `/profile`. Он не создаёт
отдельный профильный источник данных, а собирает read-model из уже существующего
пользовательского состояния активного города:

- выбранный город;
- явно выбранные интересы;
- количество избранных мест;
- количество посещённых мест.

Из профиля можно перейти к смене города, настройке интересов, избранному и истории посещений.
Данные другого пользователя или другого города в summary не попадают. Бот не выводит
скрытые интересы и не строит профиль из геопозиции или истории просмотров.


## Сохранённые маршруты

Результат конструктора можно сохранить явной кнопкой «💾 Сохранить маршрут». Бот сохраняет
только активный город, тип интереса, бюджет времени и упорядоченный список `place_slug`.
Координаты пользователя, использованные для выбора стартовой точки, в SQLite не записываются.

Кнопка сохранения получает компактный snapshot точек с checksum. Если старое Telegram-сообщение
используется после изменения порядка каталога, checksum не совпадёт и сохранение завершится
fail-closed с предложением собрать маршрут заново.

Сохранённые маршруты доступны из «👤 Мой гид», изолированы по `user_id + city_slug`,
переживают restart контейнера и могут быть удалены пользователем. При открытии snapshot
неизвестные или удалённые точки пропускаются, а оставшиеся можно открыть в Google Maps.


## Экспорт пользовательских данных

Команда `/export` и кнопка «📦 Экспорт данных» в «Мой гид» создают UTF-8 JSON-файл
для текущего активного города. Файл формируется в памяти и не сохраняется как временный
артефакт на диске контейнера.

Экспорт содержит:

- активный город;
- явно выбранные интересы;
- избранные места;
- отмеченные посещённые места;
- явные отметки «Не интересно»;
- сохранённые маршруты с исходным порядком остановок.

Для точек сохраняются стабильные `place_slug` и текущее человекочитаемое название, если
оно всё ещё есть в каталоге. Если точка была удалена или переименована, её id сохраняется,
а `title` становится `null` — бот не придумывает замену.

Экспорт намеренно не содержит Telegram `user_id`, bot token, геопозицию, FSM-координаты,
историю просмотров или конфигурацию внешних провайдеров. Формат версионируется полем
`schema_version`.


## Объяснимый персональный гид

Раздел «Для меня» использует только явные пользовательские сигналы:

- выбранные интересы;
- избранные места как небольшой приоритет;
- посещённые места как исключение из новых рекомендаций;
- явный сигнал «Не интересно» как обратимое исключение из персональной выдачи.

Для каждого рекомендованного места интерфейс показывает причины попадания в подборку
(например, совпавший интерес или наличие в избранном). Внутренний score не показывается
пользователю как «оценка качества» места.

Если место совпадает сразу с несколькими выбранными интересами, оно получает небольшой
deterministic multi-interest bonus. Геопозиция, история просмотров и скрыто выведенные
предпочтения в ranking не используются.


## «Не интересно»

Карточка места содержит обратимую кнопку «🙈 Не интересно». Это явный пользовательский
сигнал: место исключается из раздела «Для меня», пока пользователь не нажмёт
«↩️ Вернуть в рекомендации».

Сигнал хранится отдельно по `user_id + city_slug + place_slug`, переживает рестарты и
не влияет на другие города или аккаунты. Он имеет приоритет над favorite boost: место может
оставаться в избранном, но не появляться в персональных рекомендациях.

`dismissed_places` включается в JSON export (schema v2) и удаляется транзакционно через
«Управление данными». Геопозиция и история просмотров для этого сигнала не используются.


## Персональный маршрут

Из раздела «Для меня» можно открыть «🪄 Маршрут для меня» и выбрать бюджет 2, 4 или 6 часов.
Candidates берутся из текущего explainable personal ranking: явные интересы формируют
релевантность, избранное даёт небольшой приоритет, а посещённые и отмеченные
«Не интересно» места исключаются до построения.

Маршрут использует тот же алгоритм time budget, visit time и walking transitions, что и
обычный конструктор. Без геопозиции первой выбирается highest-ranked точка, которая помещается
в бюджет; далее маршрут продолжает nearest-neighbour ordering среди оставшихся кандидатов.

Персональный маршрут можно открыть в Google Maps и сохранить. В saved routes он отображается
как «🎯 Для меня». Никаких сигналов истории просмотров или скрытого профилирования не
используется.


## Персональный маршрут от геопозиции

В «🪄 Маршрут для меня» можно нажать «📍 Начать рядом со мной», один раз передать
Telegram location и затем выбрать 2, 4 или 6 часов. Геопозиция используется только как
origin для выбора первой точки и расчёта пешего времени/расстояния.

Координаты находятся только во временном FSM state: после построения, отмены, возврата
в «Для меня», перехода на главный экран или смены города state очищается. В SQLite,
JSON export и saved-route snapshot координаты не записываются.

Personal ranking остаётся прежним: candidates формируются только из явных interests и
favorites; visited и «Не интересно» исключаются до planner. При наличии origin первая
точка выбирается по расстоянию среди этих candidates, но только если дорога до неё вместе
с посещением помещается в выбранный time budget.
